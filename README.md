# MazeRunner

C++20 기반의 LWGF(Light Weight Game Framework)를 사용해 개발하는 미로 탈출 게임입니다.

- Framework: https://github.com/ChaRob/LightWeightGameFramework
- Build System: CMake
- 1차 배포 대상: Windows
- 향후 배포 대상: Android

## 1. Product Goal

제한 시간 안에 매번 새롭게 생성되는 미로를 연속으로 탈출하면서 최대한 높은 스테이지와 점수를 기록하는 게임을 만든다.

핵심 플레이 루프는 다음과 같다.

```text
미로 생성
  ↓
시작점에서 플레이 시작
  ↓
도착점까지 이동
  ↓
스테이지 클리어
  ↓
점수 획득 + 남은 시간에 보너스 시간 추가
  ↓
다음 스테이지 생성
  ↓
제한 시간이 0이 될 때까지 반복
```

게임의 최종 목표는 마지막 스테이지를 클리어하는 것이 아니라, 무한히 이어지는 스테이지에서 더 높은 점수를 기록하는 것이다.

## 2. Game Flow

1. 게임 실행 시 MAIN MENU에 START / EXIT 버튼을 표시한다.
2. START를 클릭하면 메뉴 Fade Out → 게임 Fade In 전환이 진행된다.
3. 미로를 숨긴 별도의 GET READY 화면에서 3 → 2 → 1 카운트다운 후 GO!를 잠깐 표시한다. 이때 게임 타이머와 이동은 비활성화된다.
4. GO! 표시가 끝나면 미로가 나타나며 Stage 1 게임 플레이와 제한시간이 시작된다.
5. 방향키로 이동하여 Goal에 도착하면 점수와 보너스 시간을 얻고 다음 스테이지로 진행한다.
6. 플레이 중 ESC를 누르면 미로를 아예 렌더링하지 않는 PAUSED 화면을 표시한다.
7. PAUSED에서는 제한시간과 이동을 멈추며, CONTINUE 또는 ESC로 카운트다운 없이 즉시 복귀한다.
8. PAUSED의 MAIN MENU를 누르면 현재 게임을 포기하고 Fade 전환으로 메인 메뉴로 돌아간다.
9. 제한시간이 0이 되면 RESULT에 최종 점수와 클리어한 스테이지를 표시한다.
10. RESULT는 자동 복귀하지 않으며 MAIN MENU 버튼을 눌러야 메인 메뉴로 돌아간다.
11. 메인 메뉴 START로 다시 게임을 시작하면 스테이지·시간·점수가 모두 초기화된다.

## 3. V1 Scope

### 포함

- 랜덤 미로 생성
- 시작점 / 도착점 배치
- 플레이어의 상하좌우 이동
- 벽 이동 제한
- 도착점 도달 판정
- 스테이지 진행
- 전체 게임에서 유지되는 제한 시간
- 스테이지 클리어 시 시간 추가
- 스테이지 및 클리어 속도를 반영하는 점수
- 스테이지 증가에 따른 미로 크기 증가
- V1 최대 미로 크기 제한
- 시간 초과 시 Game Over
- 최종 점수 및 도달 스테이지 표시

### 제외

V1에서는 이동과 미로 탈출 자체를 먼저 검증하기 위해 다음 상호작용은 제외한다.

- 벽 밀기
- 열쇠 / 문
- 순간이동
- 함정
- 적
- 아이템
- 전투
- 스킬
- 캐릭터 성장
- 온라인 랭킹

카메라 기능도 V1 범위에서는 제외한다. 향후 카메라 기능을 추가한 뒤 미로의 최대 크기를 확장할 수 있다.

## 4. Stage / Time / Score Policy

### Stage

- 스테이지는 무한히 진행된다.
- Stage 1~10은 5x5 논리 Cell에서 시작한다.
- 10스테이지마다 가로/세로 크기를 각각 2 Cell 증가시킨다 (Stage 11~20: 7x7).
- Stage 101부터 최대 25x25 논리 Cell로 고정한다.
- 최대 크기에 도달한 이후에도 스테이지는 계속 진행된다.
- 각 스테이지에서 새로운 Seed로 미로와 Start/Goal을 생성하고 플레이어를 Start에 배치한다.
- 최대 크기 이후 기믹 추가는 후속 범위이며, V1에서는 구현하지 않는다.
- 이번 Stage Loop에서는 시간/점수/클리어 연출을 제외하고 Goal에 도착하면 즉시 다음 스테이지로 전환한다.

### Time

게임 전체에서 하나의 제한 시간을 유지한다.

예시:

```text
Stage 1 시작: 30초
Stage 1 클리어: 18초 남음
클리어 보너스: +4초 (최단거리 20칸인 경우)
Stage 2 시작: 22초
```

초기 플레이 테스트용 값: 시작 시간 30초, 최대 보유 시간 30초, 클리어 보너스 = Start~Goal 최단 Cell 이동 횟수 × 0.20초. 다음 스테이지로 전환해도 남은 시간이 유지된다. 0초가 되면 Game Over로 전환하고 입력을 차단한다. 이 수치는 플레이 테스트 후 조정한다.

### Score

점수는 다음 두 요소를 반영한다.

- 더 높은 스테이지까지 진행할수록 높은 점수
- 더 빠르게 스테이지를 클리어할수록 높은 점수

초기 플레이 테스트용 점수 공식: Stage 클리어 시 100점 + 최단거리 × 10점 + max(0, floor((최단거리 × 0.5초 - 실제 클리어 소요 시간) × 10))점. 점수는 누적되고 추후 밸런스 조정이 가능하다.

시간 보너스(0.20초/칸)와 속도 점수 판정 기준(0.5초/칸)은 서로 다른 설정으로 유지한다. 이번 시간 보너스 밸런스 조정은 점수 계산에 영향을 주지 않는다.

## 5. Maze Requirements

생성되는 미로는 다음 조건을 만족해야 한다.

1. 미로의 외곽은 모두 벽으로 막혀 있어야 한다.
2. 시작점과 도착점은 서로 인접하지 않아야 한다.
3. 시작점과 도착점 사이의 실제 최단 이동 거리는 일정 기준 이상이어야 한다.
4. 시작점에서 도착점까지 반드시 이동 가능한 경로가 존재해야 한다.
5. 모든 이동 가능한 Cell은 서로 연결되어 있어야 한다.
6. 접근할 수 없는 고립된 통로는 생성하지 않는다.
7. 통로는 기본적으로 1타일 폭을 유지한다.
8. 2x2 이상의 넓은 열린 공간은 생성하지 않는다.
9. V1에서는 순환 경로가 없는 Perfect Maze 형태를 허용한다.
10. Goal은 이동 가능한 인접 Cell이 정확히 하나인 막다른 길에 배치한다.

시작점과 도착점 사이의 최소 거리 기준은 플레이 테스트를 통해 결정한다.

## 6. Maze Representation

게임에서 사용하는 미로 크기는 논리적인 Cell 수를 기준으로 한다.

예를 들어 5x5 Maze는 5x5개의 논리 Cell을 의미하며, 실제 렌더링용 Tile Map은 Cell 사이의 벽과 외곽 벽을 포함하여 11x11이 된다.

```text
TileWidth  = CellWidth  * 2 + 1
TileHeight = CellHeight * 2 + 1
```

5x5 Cell 기준 초기 상태 예시:

```text
###########
#.#.#.#.#.#
###########
#.#.#.#.#.#
###########
#.#.#.#.#.#
###########
#.#.#.#.#.#
###########
#.#.#.#.#.#
###########
```

각 논리 Cell 사이의 벽을 제거하여 통로를 연결한다.

### Tile Data

Maze의 Tile 데이터는 Grid 형태로 관리한다.

예정 구조:

```cpp
enum class TileType
{
    Path,
    Wall
};

std::vector<std::vector<TileType>> m_tiles;
```

플레이어는 Tile 상태에 포함하지 않고 별도의 위치 데이터로 관리한다.

시작점과 도착점 역시 Tile 종류가 아니라 Stage에서 의미를 가지는 위치로 분리하여 관리하는 방향을 사용한다.

## 7. Maze Generation

V1의 최초 미로 생성 알고리즘은 **Randomized DFS (Recursive Backtracker)** 를 사용한다.

기본 흐름:

```text
논리 Cell Grid 생성
  ↓
모든 Cell 사이가 벽으로 막힌 초기 상태 생성
  ↓
시작 Cell 선택
  ↓
방문하지 않은 인접 Cell 중 하나를 랜덤 선택
  ↓
현재 Cell과 선택한 Cell 사이의 벽 제거
  ↓
선택한 Cell로 이동
  ↓
더 이상 방문할 이웃이 없으면 이전 Cell로 되돌아감
  ↓
모든 Cell을 방문할 때까지 반복
```

미로 생성이 완료된 후 시작점과 도착점을 결정한다.

```text
Maze 생성 완료
  ↓
Start Cell 결정
  ↓
Start에서 각 Cell까지의 최단 거리 계산
  ↓
최소 거리 조건을 만족하는 Goal Cell 결정
```

첫 구현에서는 Randomized DFS를 사용하고, 실제 플레이 결과 긴 복도가 지나치게 많거나 분기 구조가 부족하다고 판단되면 다른 생성 알고리즘과 비교한다.

Goal은 Start에서 가장 먼 이동거리의 90% 이상인 후보 중에서도, 실제 열린 통로가 정확히 1개인 막다른 Cell만 선택한다. Perfect Maze에서는 가장 먼 Cell이 막다른 Cell이므로 후보가 존재한다.

## 8. Player Policy

V1의 플레이어 이동은 Grid 기반으로 구현한다.

- 플레이어는 하나의 Cell에 위치한다.
- 상 / 하 / 좌 / 우 4방향으로만 이동한다.
- 대각선 이동은 지원하지 않는다.
- 방향키를 처음 누르면 인접 Cell로 즉시 1칸 이동하고, 이후에는 0.14초의 공통 이동 간격으로 연속 이동한다.
- 새로운 방향키를 누르면 현재 누르고 있는 방향키보다 우선하지만, 실제 이동은 모든 방향이 공유하는 0.14초 간격을 따른다. 빠른 재입력에도 이동 간격을 건너뛸 수 없다.
- 벽에 막히면 더 이상 진행하지 않으며, 교차점에서는 현재 이동 방향을 유지한다.
- 스테이지가 변경되거나 일시정지에서 복귀하면 방향키를 모두 한 번 놓아야 다시 이동할 수 있다.
- 이동 대상이 Wall이면 이동하지 않는다.
- 이동 대상이 Path이면 이동한다.
- Goal Cell에 진입하는 순간 Stage Clear로 판정한다.
- 플레이어의 논리적 크기는 1 Cell이다.
- 렌더링 시 플레이어 이미지는 Tile보다 조금 작게 표현할 수 있다.

V1에서는 실제 크기 기반의 물리 충돌, 이동 속도 및 연속적인 좌표 이동은 구현하지 않는다.

향후 필요할 경우 Grid 기반 Maze 구조는 유지하면서 Player 이동만 World Position 및 Collision 기반으로 확장한다.

## 9. Random Seed

랜덤 미로에서 발생하는 문제를 재현할 수 있도록 미로 생성 Seed를 지정할 수 있는 구조를 고려한다.

- 일반 플레이: 랜덤 Seed 사용
- 디버깅: 특정 Seed를 지정하여 동일한 미로 재생성

## 10. V1 Completion Criteria

다음 조건을 만족하면 V1의 기본 게임 루프가 완성된 것으로 판단한다.

- 프로그램에서 랜덤 미로를 생성할 수 있다.
- 미로 외곽이 모두 벽으로 막혀 있다.
- 모든 이동 가능한 Cell이 연결되어 있다.
- 시작점에서 도착점까지 이동 가능한 경로가 존재한다.
- 시작점과 도착점이 충분한 이동 거리를 가진다.
- 플레이어가 벽을 통과하지 않고 상하좌우로 이동할 수 있다.
- 플레이어가 Goal에 도달하면 다음 스테이지가 생성된다.
- 스테이지 진행에 따라 미로 크기가 설정된 최대 크기까지 증가한다.
- 스테이지가 변경되어도 남은 시간이 유지되고 클리어 보너스 시간이 추가된다.
- 점수가 스테이지 진행도와 클리어 속도를 반영한다.
- 제한 시간이 0이 되면 게임이 종료된다.
- 게임 종료 시 최종 점수와 도달 스테이지를 확인할 수 있다.

## 11. Initial Development Order

전체 시스템을 한 번에 구현하지 않고 미로 생성부터 작은 단위로 검증한다.

### Step 1 - Maze Prototype

1. Maze 데이터 구조 정의
2. 빈 Maze 초기화
3. Randomized DFS 미로 생성
4. 생성된 미로 렌더링
5. 반복 실행을 통해 서로 다른 정상적인 미로가 생성되는지 확인

완료 기준:

> 프로그램 실행 시 랜덤한 미로가 생성되고, 외곽이 막혀 있으며, 모든 Cell이 연결되어 있고 통로 폭이 1칸이다.

### Step 2 - Start / Goal / Player

1. Start 결정
2. Cell 간 거리 계산
3. 거리 조건을 만족하는 Goal 결정
4. Player를 Start에 배치
5. 방향키 Grid 이동 구현
6. Wall 이동 제한
7. Goal 도달 판정

### Step 3 - Stage Loop

1. Goal 도달 시 Stage Clear 판정
2. Stage 증가 및 새로운 Seed를 사용한 Maze/Start/Goal 생성
3. Player를 새 Start에 배치
4. 10스테이지마다 2 Cell씩 증가, 25x25에서 크기 제한

### Step 4 - Game Rules

1. 제한 시간
2. Stage Clear 시간 보너스
3. 점수 계산
4. Game Over
5. 최종 결과 표시

LWGF의 Font 및 Renderer2D::DrawText()로 Stage/Time/Score 숫자 HUD, 시간 게이지, 결과 화면을 출력한다. HUD 폰트는 CMake 빌드 시 실행 파일 옆 assets/fonts에 복사하여 작업 디렉터리에 의존하지 않도록 한다. 향후 배포용 에셋으로 정식 분리할 예정이다.

### Step 5 - Menu / Presentation

- 게임 실행 시 MAIN MENU (START / EXIT)
- Fade Out → Fade In (각 0.35초), 이후 미로가 보이지 않는 GET READY 화면에서 3초 카운트다운 + GO! 0.4초
- PLAYING 도중 ESC → PAUSED (미로·플레이어 렌더링 금지, 게임 타이머 정지)
- PAUSED의 CONTINUE 또는 ESC → 즉시 재개 (재개 프레임 이동 입력 차단)
- PAUSED의 MAIN MENU → 진행 중 게임 포기 후 메뉴 복귀
- 제한시간 0초 → RESULT (클리어 스테이지 / 최종 점수)
- RESULT의 MAIN MENU 버튼으로만 복귀 (자동 복귀 없음)
- 재시작 시 GameSession을 새로 생성하고 점수·스테이지·타이머 초기화
- V1 버튼은 LWGF 마우스 좌표/클릭 입력과 ASCII Font로 구현

Fade와 Countdown 동안 제한시간이 감소하지 않으며, 화면 전환 중 중복 입력을 받지 않는다.

## 12. Future Considerations

V1 플레이 테스트 이후 필요성을 확인하고 다음 기능을 검토한다.

- 카메라 이동 및 더 큰 미로
- 최대 미로 크기 이후 난이도 조절
- 다른 미로 생성 알고리즘
- 물리적 이동 및 벽 Collision
- 벽 밀기
- 열쇠 / 문
- 순간이동
- 함정 / 아이템 등 추가 미로 기믹

기능은 실제 플레이에서 필요성이 확인된 이후 추가한다.

## 13. Player Test Notes (Goal + Hold Movement)

- 5x5, 7x7, 25x25 크기에서 다양한 Seed로 Goal의 단일 출구 및 최단거리 조건 확인
- 키 최초 입력 즉시 한 칸, 이후 모든 방향 공유 0.14초 간격으로 반복 이동 확인
- 교차점에서 진행 방향 유지, 새 방향키는 우선하되 공통 이동 간격이 지켜지는지 확인
- 벽에 막혀도 벽을 통과하지 않는지 확인
- Goal을 밟아 다음 스테이지로 넘어간 뒤 키를 놓기 전에는 이동하지 않는지 확인
- 일시정지/복귀 및 카운트다운 후 홀드 입력이 새 게임으로 넘어가지 않는지 확인
- 게임 타이머의 30초 시작·최대 제한 및 점수 정책은 그대로, 클리어 시간 보너스만 0.20초/칸으로 조정

## 14. Countdown Display / Shared Input Cooldown

- 플레이 시작 전에는 미로 및 HUD를 전혀 그리지 않고 GET READY / 3 → 2 → 1 / GO!를 독립적인 화면으로 표시한다.
- 3초 카운트다운과 0.4초 GO! 표시가 끝난 다음부터 게임 시간을 차감한다.
- 카운트다운/GO! 중에는 방향키 이동을 허용하지 않는다.
- 0.14초 이동 간격은 방향 전환이나 키를 잠깐 떼었다 다시 눌러도 공유한다. 길게 누른 경우에도 프레임당 최대 한 칸만 이동한다.
- 새 스테이지 진입 또는 일시정지 복귀 후에는 모든 방향키를 뗀 다음 재입력해야 한다.

## 15. Developer Tuning (internal only)

게임 밸런스 테스트를 위해 **`src/game/GameTuning.h` 하나에서 수치를 변경**할 수 있다.

- `Movement::RepeatIntervalSeconds`: 방향키 홀드 및 방향 전환에 공통으로 적용하는 이동 간격 (기본 0.14초)
- `Time::InitialSeconds` / `MaximumSeconds` / `ClearBonusSecondsPerCell`: 최초 30초, 최대 30초, 클리어 시 0.20초/칸
- `Score::BasePointsPerStage` / `DistancePointsPerCell` / `SpeedBaselineSecondsPerCell` / `SpeedPointsPerSecondSaved`: 기본 점수, 거리 점수, 속도 평가 기준 (시간 보너스와 독립)
- `Maze::InitialCellSize` / `MaximumCellSize` / `CellGrowthPerTier` / `StagesPerTier` / `GoalMinimumDistanceRatio`: 스테이지에 따른 미로 크기 및 Goal 거리 비율
- `Transition::FadeSeconds` / `CountdownSeconds` / `GoSeconds`: 페이드, 시작 카운트다운, GO 표시 시간

**사용법**: 헤더에서 원하는 값을 바꾼 뒤 CMake 프로젝트를 다시 빌드하고 게임을 실행한다. 별도 설정 파일을 로딩하지 않으며 값은 실행 파일에 컴파일되므로 배포된 게임 사용자가 설정 파일로 게임 규칙을 수정할 수 없다.

헤더에 `static_assert`를 포함해 유효하지 않은 값은 컴파일 단계에서 감지한다. 예를 들어 이동 간격은 0보다 커야 하고, 최대 시간은 시작 시간 이상이어야 하며, 미로 크기 증가 폭으로 최대 크기에 도달할 수 있어야 한다. 카운트다운은 1~9초의 정수로 제한한다. 테스트도 대부분 헤더의 설정값을 기준으로 검증하도록 변경했다.

UI 색상·테마 및 외부 JSON 설정 파일은 포함하지 않는다. 향후 테마 전환이 필요해질 경우 UI 설정을 별도 설계한다.

## 16. Stage Clear Notice (non-blocking)

- Goal에 도달하면 기존과 동일하게 점수·시간을 즉시 정산하고 다음 스테이지를 즉시 생성한다.
- 새 미로가 표시되는 동안 상단 HUD 아래에 반투명 클리어 알림을 1초간 표시한다.
- 알림에는 **방금 클리어한 스테이지**, **실제로 증가한 점수**, **최대 시간 제한을 반영해 실제로 추가된 시간**을 표시한다.
- 알림의 마지막 0.2초에는 자연스럽게 투명해지고 자동으로 사라진다.
- 알림은 게임 상태를 변경하지 않는다. 게임 타이머와 이동은 계속 동작하며, 별도 Fade나 카운트다운을 넣지 않는다.
- 스테이지 전환 직후 방향키를 한 번 놓아야 한다는 기존 정책도 유지한다.
- 1초 내에 다시 클리어하면 알림을 중첩하지 않고 최신 클리어 정보로 교체하며 표시 시간을 다시 1초로 시작한다.
- 메인 메뉴 또는 결과 화면에서는 남은 알림을 지운다. 일시정지 중에는 알림을 그리지 않으며 실제 시간 기준으로 소멸한다.
- 알림 표시 시간은 `GameTuning::Transition::ClearNoticeSeconds`에서 변경할 수 있다.

## 17. Player Movement Feel (smooth rendering + buffered turns)

- 격자 이동, 벽 통과 금지, 4방향 이동, Goal 진입 즉시 클리어 등 기존 게임 규칙을 유지한다.
- 이동 간격은 플레이 테스트에서 정한 `GameTuning::Movement::RepeatIntervalSeconds = 0.14f`를 사용한다.
- 플레이어의 논리적 위치는 Cell 좌표로 즉시 변경되지만, 화면에 표시되는 캐릭터는 인접 Cell 중심 사이를 이동 간격 동안 선형 보간한다.
- 시각적 보간은 축 하나를 따라 진행하므로 직각 코너를 대각선으로 가로질러 표현하지 않는다.
- 두 방향을 누른 채 진행할 때 가장 최근에 누른 방향이 막혀 있다면 이전의 통과 가능한 방향으로 계속 이동한다. 우선 방향의 통로가 열리는 순간 자동으로 꺾는다.
- 새 방향을 놓으면 예약된 방향 전환은 취소된다. 이동 불가능한 방향으로 벽을 통과하거나 입력 간격을 우회하지 않는다.
- 일시정지, 새 스테이지 진입, 카운트다운/메뉴 복귀 시 남은 화면 보간을 리셋하며, 스테이지 전환 직후 모든 방향키를 한 번 놓아야 하는 정책은 유지한다.
- Window Title은 현재 LWGF `Application::Initialize()` 내부의 고정 문자열이다. 프레임워크에 게임별 창 제목 지정 API가 제공된 다음 MazeRunner에서 `MazeRunner`를 전달한다 (이 PR에는 포함하지 않음).
